# ひろしま協働DXプロジェクト LP — 画像アセットについて

最終更新: 2026年8月30日

## 背景は画像ではなく、CSSで描いています

このLPの背景は「海面から深海へ潜っていく1本のグラデーション」です。
**画像ファイルではなくCSSで描いています。**

理由は3つあります。

1. **継ぎ目が原理的に発生しない。** 画像を section ごとに敷くと境目に線が出ますが、
   グラデーションはページ全体で1枚なので、どこにも境目ができません
2. **解像度に依存しない。** どんな画面幅・ページ丈でも破綻しません
3. **スマホ専用の背景画像が要らない。** 同じグラデーションが縦に伸びるだけです

水面から差し込む光と、漂う粒子も同様にCSS／SVGで描いています。

編集する場合は `style.css` の冒頭にある色のトークンを変えてください。

```css
--sea-0:#FBF6E9;  --sea-p0:0%;
--sea-1:#E4EFE9;  --sea-p1:10%;
--sea-2:#C6E2EC;  --sea-p2:20%;
--sea-3:#A5D0E2;  --sea-p3:28%;
--sea-4:#79B2D2;  --sea-p4:42%;
--sea-5:#4C8CBC;  --sea-p5:54%;
--sea-6:#245C93;  --sea-p6:62%;
--sea-7:#071C3C;  --sea-p7:100%;
```

> **色と停止位置は `tools/check.js` も読みます。** 検証ツールは `:root` の
> `--sea-0〜7`（色）と `--sea-p0〜7`（停止位置）から実際の下地を計算するので、
> CSSを直せば判定も自動で追随します。値を別の場所に書き写さないでください。
>
> **停止位置はセクションの階層に合わせてあります**（浅瀬0〜25% / 中層25〜58% /
> 深海58〜100%）。ここがずれると、深海セクションの見出しが明るい水の上に乗って
> コントラストが足りなくなります。

## 画像ファイルの一覧

背景をCSSにしたことで、画像は**25点だけ**になりました（以前は50点・約3MB）。

### ヒーローの一枚絵

| ファイル | 寸法 | 使用箇所 |
|---|---|---|
| `backgrounds/hero-scene-wide.jpg` | 1600×900 | PC・横長画面。ヒーロー全面 |
| `backgrounds/hero-mobile.jpg` | 900×1599 | 縦長画面。ヒーロー全面 |

どちらも**船だけが描かれていない絵**に、`LP\アイテム` の船アイコンを
合成したものです。文字はHTMLで置き直しています（画像内文字を禁じる
ルールのため）。再生成は `tools/build-hero-wide.ps1`（横）と
`tools/build-hero-mobile.ps1`（縦）。

横の絵の元は `LP\背景画像\ChatGPT Image 2026年8月26日 13_11_05.png`
（1672×941）。以前は文字が焼き込まれた完成イメージから文字を消して
使っていました（`tools/build-hero-full.ps1`）が、船が絵に固定されていて
配置を直せませんでした。船の無い絵に切り替えたことで、船団の並びを
スクリプトで調整できます。

以前は船団のある右半分だけを切り出し、左はページのクリーム色に任せて
いました。けれど絵の左端がどう減衰しても、そこで絵が終わることに変わりは
なく、画面がくっきり左右に割れて見えました。元絵はもともと「破れた紙 +
海」で1枚に描かれているので、文字だけ消して全面に敷けば、紙から海への
移り変わりは絵の中の破れた縁がそのまま担ってくれます。継ぎ目は原理的に
存在しなくなります。

**本文の位置は絵の中の紙に合わせてあります。** cover は必ず絵の横中央を
画面の横中央に持ってくるので、紙の右端は画面幅によらず同じ vw の位置に
来ます（今の絵では 44〜45vw あたり）。ヒーローだけ .wrap を外し、
`padding-left` と `.hero-panel` の `max-width` を vw で指定しているのは
このためです。絵を差し替えたら、この2つの値も測り直してください。

**ヒーローの高さは画面ではなく絵で決めています**（`min-height:clamp(940px,
74vw, 1060px)`）。絵の下の帯には原爆ドーム・鳥居・広島城が並んでいて、
ヒーローが低いと cover が絵を縮めて建物が上がってきて、リード文の下に
食い込みます（1280px で 1.52:1 まで落ちました）。高さを確保すると絵が
拡大され、建物は本文より下へ逃げます。

### 絵に焼き込んだ船団

どちらの絵も、夕日へ向かって遠ざかる並びに船アイコンを合成しています
（横＝26点、縦＝8点）。素材の絵には船が描かれていないので、`LP\アイテム`
の船アイコンを重ねています。生成は `tools/build-hero-wide.ps1` と
`tools/build-hero-mobile.ps1`。

横の絵は**奥から手前へ4段**で組みます（遠景13・中遠景6・中景4・手前3）。
段の間隔は「上の段の船底 ＋ 下の段の舟の高さ」で決まります。舟はマストが
高く、高さが幅の約2.7倍あるので、これを割ると必ず上の段へ突き上げます。
さらに中景は、中遠景の舟と舟の**間**に置きます。真下に置くとマストが
刺さって 13〜46% の重なりになり、検査で止まります。

**船はCSSで重ねず、絵に焼き込んでいます。** 背景は cover で表示するため、
画面の縦横比によって左右が切り取られます。CSSの % で船を置くと画面の
座標系に従うので、絵の切り取りとずれて「陸に乗り上げた船」になりかねません。
絵の中に描いてしまえば、絵と一緒に切り取られるので、どんな画面でも船は
必ず同じ海面の上にいます。

**陸に掛からないことは目視ではなく実測で担保しています。**

1. 水平線より下について、画素の色から「水かどうか」の地図を作る
   （緑が青より強い＝島の緑、暗い＝建物や木立。ただし夕日の光路は
   白く輝いていて緑寄りに出るので、明るい画素は陸から除く）
2. 六角アイコンと橋は色だけでは水と区別できないので、明示的に除外区画を置く
3. 各船の喫水線（外接矩形の下側30%）が水の上にあるかを数える
4. 97% を割ったら、その場で止めて位置を報告する

**船どうしの重なりも実測しています。** 外接矩形では判定になりません
（帆の上は透明な余白が広く、矩形が重なっていても絵は重なっていない）。
置く大きさに縮めた不透明画素そのものを占有マップに積み、先に置いた船と
何％重なるかを数えて、9%を超えたら止めます。

横の絵では、紙が明るいクリーム色で「陸ではない」と判定されてしまうため、
紙の縁を折れ線（`$PaperEdge`）で明示的に除外しています。また、波の谷は
暗い青なので「暗い＝陸」の規則だけでは水を陸と誤読します。暗い場合は
青が赤より強いことも条件に加えてあります。

位置を決めるときは `-Map` を付けて実行すると、水の地図がASCIIで出ます。

```bash
powershell -File tools/build-hero-wide.ps1 -Map
powershell -File tools/build-hero-mobile.ps1 -Map
```

帆が遠くの島に重なるのは許しています。手前の船として自然に見えるためです。
判定しているのは船底だけです。

紙は下へいくほど狭まり、左下には原爆ドームが入ります。狭い画面では
リード文がそこへ届いてしまうので、768〜1279px では余白と字を詰めて
あります。`tools/onpaper.js` が、文字の下が本当に紙かどうかを
背景画像から実測して判定します。

## 画像の形式（2026-09-05 にWebPへ移行）

装飾の画像はすべて **WebP**（品質0.92）です。PNGのままだと、生き物と挿絵だけで
5.0MB あり、スマホの回線では重すぎました。変換後は 1.25MB（-75%）です。
透明度は元と完全に一致し、色の差は平均 1.5〜2.9／255（画面では見分けられない）
であることを画素単位で測って確認しています。

PNGのまま残しているのは、ロゴマーク（favicon にも使うため）と、いただいた
2つのロゴだけです。

**差し替えるときも WebP にしてください。** ファイル名と保存先は変えないこと
（HTML が名前を直接指定しています）。変換の道具は `tools/webp-bridge.js` に
説明があります。この環境には cwebp も ImageMagick も無いので、ブラウザの
エンコーダを使います。


## 挿絵の合成について

浅瀬・中層のカードは明るい地なので、挿絵を `mix-blend-mode: multiply` で重ね、
白い余白を消しています。深海の紺地では multiply だと沈むため、そのまま重ねて
明るさを少し補っています（`style.css` の `.vignette` 周辺）。

**挿絵を差し替えるときは、背景を白にしてください。** クリーム色や灰色にすると、
浅瀬・中層のカードでその領域だけ暗く沈みます。

## 画像を使っていない意匠

以下は画像ではなく **CSS／インラインSVG** で描いています。拡大しても滲まず、
色の変更もコードだけで済みます。

- 海の深度グラデーション、水面の光、漂う粒子
- 丸い見出しラベル（eyebrow）、番号バッジ、金の矢印
- チェックリストのチェックマーク、時期ラベルのピル
- CTAの矢印（`.chev`）
- 対象診断のアイコン（羅針盤・帆船・灯台・地図ピン・閉じる）

診断のアイコンは `index.html` の先頭にある `<svg class="sprite">` に
`<symbol>` として置き、`<use href="#ic-...">` で呼び出しています。
`currentColor` で描いているので、置いた場所の文字色にそのまま追随します。

## 差し替えの基本ルール

**ファイル名・拡張子・保存フォルダを変えないでください。** HTMLとCSSが
ファイル名を直接指定しているため、名前が変わると表示されなくなります。

## 検証のしかた

ローカルで配信してから、ブラウザのコンソールで検証スクリプトを実行します。

```bash
node tools/serve.js
```

http://localhost:4173 を開き、コンソールで次を実行してください。

```js
fetch('tools/verify-all.js').then(r=>r.text()).then(t=>{eval(t);return __verify()}).then(console.log)
```

`合否: '合格'` なら通っています。落ちた場合は、どの検査が何を見つけたかが出ます。

3つの検査をまとめて回します。別々の壊れ方をするので、片方だけ直して
もう片方を壊さないよう、必ず一緒に見てください。

| 検査 | 見るもの |
|---|---|
| `tools/check.js` | コントラスト比・横スクロール・タップ領域・画像内文字・絶対パス・画像の読み込み |
| `tools/overlap.js` | 海の生き物が文字の下地を汚していないか（画像の画素を実測して合成する） |
| `tools/onpaper.js` | ヒーローの文字が絵の中の紙の上に乗っているか |

`overlap.js` は生き物どうしの重なりも見ます。水彩が重なると透けて濁った塊に
見えるためです。アニメーションで動く範囲まで含めて判定するので、周期のどこかで
重なるものも拾えます。

`check.js` は「CSSで宣言された背景色」しか見ないので、背景に敷いた画像は
見えません。生き物とヒーローの絵はそれぞれ別の検査で担保しています。

確認する画面サイズは 1920×1080 / 1440×900 / 1100×800 / 834×1112 / 390×844 / 360×640 です。

> **style.css はページを再読み込みしても再取得されないことがあります。**
> `__verify()` は毎回 `<link>` のURLを変えて読み直させます。手で確かめる
> ときも同じ用心をしてください。直したはずのCSSではなく古いCSSを測って
> しまい、実際に一度それで判断を誤りました。

## 海の生き物の増やし方・動かし方

生き物は13種類の画像を、大きさ・向き・濃さ・速さを変えて37か所に置いて
います。ブラウザは同じURLを1回しか読まないので、同じ絵を何度置いても
通信量は増えません。

**大きな意匠（`b1`）は深さの物語に合わせてあります。**

| 階層 | 置くもの | 動き |
|---|---|---|
| 浅瀬 | 青いカニ | 横歩き（`a-crawl`） |
| 中層 | ザトウクジラ・赤いカニ | 大きくゆっくり回遊（`a-glide`）／横歩き |
| 深海 | 熱水噴出孔・海底火山 | 根を張ったまま噴出だけが息をする（`a-plume`） |

実際の海の縦の並びと同じなので、説明しなくても深く潜っていることが
伝わります。生成は `tools/build-creatures-big.ps1`（不透明部分へ切り詰めて
縮小するだけ）。

**見せ場を置いた階層では、スマホで点景を隠しています。** 幅が狭いと下端に
全部が集まり、水彩どうしが重なって濁るためです。

クラスは2つに分かれています。

| 種類 | 例 | 役割 |
|---|---|---|
| 動き | `a-swim` / `a-drift` / `a-sway` / `a-crawl` / `a-glide` / `a-plume` | どう動くか（@keyframes 6種） |
| 位置 | `s1`〜`s5`（点景）/ `b1`（見せ場） | セクション内のどこに置くか |

位置は `style.css` の `.sec-xxx .s1 { --cr: … }` で与えます。増やすときは
HTMLに1行足し、CSSに位置を1行足してください。

**置き場所は「カードが無い水域」を狙います。** 見出しとリード文は左寄せで
幅44emまでなので、広い画面では見出しの右側がまるごと空きます。逆に狭い
画面ではその余白が無くなるため、大きい個体はセクションの下端へ回して
境目をまたいで泳がせています。

動きは `transform` だけで、レイアウトには一切関わりません。
`prefers-reduced-motion: reduce` の指定がある環境では止まります。
